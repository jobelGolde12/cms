# QA Pass and Fixes — November 5, 2026

This file records the defects found during the deep QA audit that followed the
demo-account cleanup, and what was changed for each of them.

---

## 1. Form data destroyed by React 19's automatic form reset (critical)

**Symptom.** Pressing Submit on any form wiped the fields the user had
filled in — even when the server rejected the submission with a validation
error. The person was left with an empty form, an error message, and no way
to tell what had been lost.

**Cause.** React 19 calls `form.reset()` through `requestFormReset()` as soon
as a `<form action={serverAction}>` starts (see `startHostTransition` in
`react-dom-client`). `form.reset()` restores every uncontrolled field to its
`defaultValue`, so the typed values disappear at the exact moment the request
is sent — before the server has even answered.

**Fix.** `form.reset()` dispatches a *cancelable* `reset` event, so cancelling
that event keeps the input intact while the request is in flight and after a
rejection. `src/components/ui/form-reset-guard.ts` adds a small hook:

```tsx
const { formRef, onReset, resetNow } = useFormResetGuard();
<form ref={formRef} action={formAction} onReset={onReset}> … </form>
```

`resetNow()` performs an explicit reset for the cases where a clean slate is
wanted (a successful create in page mode).

The guard is applied to the login form, the student form, the employee form,
the 201-file modals, the service-credit modals, the guidance incident form,
the health and clinical record forms, the section dialog, the profile and
security settings, the verification review form and the QR panel.

**Verified in the browser.** Submitting the student form with an invalid LRN
kept `First name = QATest`, `Middle name = Middle`, `Last name = Student`,
`LRN = 12345`, `Contact number = 0917 000 0000` and
`Address = Purok 1 Test Address` on screen while showing
“LRN must be exactly 12 digits”. The same holds for the user account form.

## 2. “Uncheck Active” silently re-activated an account (critical)

`userFormSchema` declared `isActive: z.boolean().optional().default(true)`, but
a `FormData` value is always a string — and an unchecked checkbox sends
*nothing* at all. The field therefore fell through to the `default(true)` and
the account stayed active.

**Fix.** The schema now accepts the raw FormData strings and converts them
(`"true" | "false" | "on" | "off" | "1" | "0" | boolean`), and the form sends a
hidden `isActive=false` next to the checkbox, so the flag is always present.
A missing value still defaults to active.

**Verified.** Creating an account with “Account is active and may sign in”
unchecked wrote `is_active = 0`; re-checking it in the edit dialog wrote
`is_active = 1`.

## 3. User Management had no UI at all (critical)

`src/actions/users.ts` already contained `createUser`, `updateUser` and
`deactivateUser` — all correctly guarded by `getAuthorizedUser("users.manage")`
— but **no page ever called them**. `/users` was a read-only list. With the
demo accounts gone, the school had exactly one way in and no way to onboard
staff.

**Fix.** `src/components/users/user-management.tsx` adds the missing screen:

* **New Account** — name, e-mail, role, phone, temporary password, active flag.
* **Edit** — the same fields; a blank password keeps the current one.
* **Disable** — deactivates (never deletes) an account, with a confirmation
  dialog; the account can be re-enabled afterwards.
* The signed-in administrator cannot disable their own account (the control
  shows a dash instead), and the server refuses it as well.
* The role list is filtered to the ten roles the application actually knows —
  the `roles` table still contained the retired `barangay`/`lgu` rows, which
  the schema rejects, so offering them was a dead choice.

`listUsersWithRoles()` now also returns the middle name and phone so the edit
form can be pre-filled.

## 4. QR Studio promised a control that did not exist

`/qr` states “QR codes are generated per verified student from their profile
page”, but the profile page had no generate button — `generateQr` and
`deactivateQr` were unreachable code.

**Fix.** `src/components/qr/qr-actions.tsx` adds the control to the student
profile: **Generate / Re-issue QR** (only for records whose status allows a
label) and **Revoke QR** (only while a token is live), plus the live token and
its `/verify/{token}` link. Both buttons share one form and one action state,
so the message on screen always belongs to the button that was pressed.

**Verified.** Generating wrote a `generate / valid` row and the profile showed
the live token; revoking wrote a `revoke / revoked` row, and the profile
reported “QR tokens revoked.”

## 5. Guidance incidents could not be removed

`removeGuidanceIncident` existed (with the correct role chain:
`behavior.write` + guidance/admin/school_admin) but had no button.

**Fix.** `src/components/guidance/incident-delete-button.tsx` adds a delete
control with a confirmation dialog to the Guidance Office roster. The removal
is audit-logged.

**Verified.** A temporary incident was recorded through the UI, removed through
the UI, and `behavior_records` returned to its original count of 12; the
removal appears in `audit_logs` as `REMOVE_GUIDANCE_INCIDENT`.

## 6. The registry hid the identifier the school actually uses

The registry's first column showed an em dash for all 25 students because none
of them has an LRN on file — no identifier at all, and the search box did not
cover the LRN.

**Fix.**

* The column is now **LRN / Student No.** and shows the student number with an
  explicit **“LRN not filed”** caption when the LRN is missing — a labelled
  fallback instead of a silent blank.
* The registry search now matches the LRN as well as the name and the student
  number.
* The column headers no longer carry sort arrows that secretly sorted by
  creation date; sorting is an explicit **Sort records** dropdown (Recently
  added / Oldest first / Name A–Z), matching the pattern already used by the
  Employees and Service Credits lists.

**Verified.** With one student temporarily given the LRN `136018051744`,
`/students?q=136018051744` returned exactly that student and the column showed
the LRN instead of the “LRN not filed” caption. The LRN was then reset to
`NULL` (no student has an LRN on file).

## 7. React Compiler lint rules rejected the new hook usage

`react-hooks/refs` flags `ref={guard.formRef}` — the rule cannot prove that a
property of a hook result is a ref. Destructuring the hook result
(`const { formRef, onReset } = useFormResetGuard()`) satisfies it, and the
hook now returns its members separately everywhere.

`react-hooks/set-state-in-effect` flagged the student form's "start a clean
form after a successful save" effect. The reset was moved into the action
wrapper itself, which ties it to the submission that caused it.

## 8. Lint hygiene

* `eslint.config.mjs` ignores the git-ignored scratch directories
  (`.tmp-qa/**`, `.tmp-integration/**`, `scripts/tmp/**`) and the local export
  directory (`database-backups/**`).
* `database-backups/` was added to `.gitignore` — the database export must
  never be committed.
* The pre-existing warnings in `scripts/db-integrity-check.mts`,
  `scripts/qa-user.mts` and `test-pdf.ts` were removed.

`npm run lint` now reports **zero problems**.

## 9. Seed scripts could resurrect the deleted accounts (critical)

`scripts/seed.mts` created one demo account per role with the fallback
address `<role>@local.dev` and the fallback password `password123`, and
`scripts/seed-remote-reference.mts` did the same. Running a seed would have
brought the removed logins straight back.

**Fix.**

* An account is created **only** when both `DEFAULT_<ROLE>_EMAIL` and
  `DEFAULT_<ROLE>_PASSWORD_HASH` are configured. There is no fallback address
  and no shared password any more; skipped roles are reported on the console.
* A deny-list (`RETIRED_DEMO_EMAILS`) covers the seven removed addresses plus
  the whole `*@local.dev` domain, so even an explicitly configured retired
  address is refused with a message.
* The remote reference seed no longer resets the password of an account that
  already exists, and it reads the correct `DEFAULT_<ROLE>_FIRST_NAME` /
  `_LAST_NAME` variables (it previously looked up `TEACHER_FIRST_NAME`, which
  is never set).
* The destructive dev seed refuses to run against a remote database unless
  `ALLOW_REMOTE_SEED=1` is set. `npm run seed:reference` is the safe tool
  there.
* The demo-data writer no longer assumes that every role account exists: it
  falls back to a surviving account for the foreign keys and reports when
  there is no account at all.

## 10. Reusable cleanup script

`scripts/delete-dummy-users.ts` was rewritten. The old version targeted a
stale hard-coded id list (including accounts that did not exist), pointed at a
hard-coded backup path from a previous run, and used `require()` in an ES
module. The new version takes its targets from the command line, refuses to
run when every active administrator is targeted, re-points the RESTRICT
columns, runs in dry-run mode by default and can require an existing backup.
